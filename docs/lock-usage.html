使い方

投稿ごとのロック、更新日の手動変更、全投稿の一括ロック・解除、日付の不整合の修復について解説します。

ロックの考え方

状態 投稿を保存したときの更新日
ロック ON（公開済み） 変わりません。
ロック OFF（公開済み） 保存した日時になります（WordPress 標準の動作）。
未公開（下書き・レビュー待ち・予約） ロックの状態に関係なく WordPress 標準の動作で、ロックは公開後に有効になります。公開操作をした場合は、その時点の日時が更新日になります。予約投稿が自動で公開された場合、ロック ON なら更新日を公開日時以降に揃え、ロック OFF なら WordPress 標準どおり最後に保存した日時のままです。

個別ロック操作

投稿の編集画面にある「Kashiwazaki SEO Lock Modified Date」メタボックスで、投稿ごとにロックを切り替えます。

1

投稿の編集画面を開き、「Kashiwazaki SEO Lock Modified Date」メタボックスを確認します。

2

「更新日をロックする」のチェックを切り替えます。切り替えた時点で保存されます（投稿の保存は不要です）。メタボックスに「ロックを有効にしました」などのメッセージが表示されます。

ヒント

切り替えの保存中は、投稿の保存ボタンが一時的に使えなくなります。メッセージが表示されてから投稿を保存してください。

更新日の手動変更

更新日を任意の日時に変更できます。コンテンツを大幅にリライトしたときなどに使います。

1

メタボックスの「更新日を手動で変更」で日時を選びます。公開日と同じにしたい場合は「公開日と同じにする」を押します（公開日時を秒まで同じにします）。

2

「更新日を変更」を押します。押した時点で反映されます（投稿の保存は不要です）。

3

変更と同時にロックが自動で ON になります。以降に投稿を保存しても、手動で指定した更新日は変わりません。ロックを解除すると、次に保存したときに更新日が保存時刻になります。

注意
  • 日時を選んだだけでは反映されません。「まだ反映されていません」と表示されている間に投稿を保存すると、警告が表示されます。
  • 未来の日時は指定できません。公開日より前の日時を指定した場合は、公開日時に合わせます。
  • 公開前の投稿は更新日を変更できません。公開後に変更してください。

一括ロック・解除

設定画面から、対象の投稿タイプのすべての投稿を一括でロック・解除できます。投稿一覧の「一括操作」からも、選んだ投稿のロック・解除ができます。

1

管理画面の「Kashiwazaki SEO Lock Modified Date」を開きます。

2

「すべてロック」または「すべてロック解除」を押し、確認ダイアログで承認します。処理が終わると件数が表示されます。

操作 効果
すべてロック 対象の投稿タイプのすべての投稿をロック ON にします。
すべてロック解除 対象の投稿タイプのすべての投稿をロック OFF にします。以降の保存で更新日が通常どおり変わります。

日付の不整合の確認・修復

設定画面の「日付の不整合を確認・修復」に、更新日（GMT）が記録されていない投稿と、更新日が公開日より前になっている投稿の件数が表示されます（ロック OFF の投稿も含みます）。「修復する」を押すと、GMT の更新日を補い、公開日より前の更新日を公開日時に合わせます。ロックの状態は変わりません。自動では書き換えないため、件数を確認してから実行してください。

運用上の注意点

項目 説明
post_modified_gmt post_modified と合わせて post_modified_gmt もロック・変更されます。
公開日を変更した場合 ロック中でも、公開日を更新日より後に動かすと、更新日は公開日時に揃います。
下書きに戻して再公開した場合 未公開の間はロックが効かないため、再公開した時点の日時が更新日になります。
対象外にした投稿タイプ 設定でチェックを外した投稿タイプは、ロック設定が残っていても更新日が通常どおり変わります。再度チェックすると元の設定で有効に戻ります。
メディア（添付ファイル） 設定で「メディア」を対象にすると、添付ファイルの編集時にも更新日がロックされます。
リビジョン ロック中の保存で本文が変わらなければリビジョンは増えません。更新日の手動変更や修復では、リビジョンがまだ 1 件も無い投稿に限り、通常の更新と同じく最初のリビジョンが作られることがあります。
サイトマップ・キャッシュ 手動変更と修復は、更新日だけを書き換えたあとに WordPress の更新フック（save_post など。メディアは attachment_updated など）を発火するため、更新を検知するサイトマップやキャッシュ系のプラグインにも反映されます。本文やタイトルには触れません。
REST API・クイック編集 ブロックエディタ、クイック編集、一括編集、REST API、WP-CLI からの更新でもロックは有効です。
